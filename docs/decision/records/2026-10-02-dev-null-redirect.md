# /dev/null へのリダイレクト

## Context

出力を捨てるための ">/dev/null" と "2>/dev/null" が、切り詰めとして hook に拒否されていた。
この操作は通常ファイルの既存データを失わせないが、エージェントのコマンドでは頻繁に使われる。
切り詰めの検出全体を無効にせず、宛先を限定した例外で誤検知を減らす。
利用者が例外の方針を承認したため、[REQ-001](../../ir/judgment.md#REQ-001) に反映する。

## Agreements

- A1 展開のないリテラルの宛先が引用除去後に "/dev/null" と完全一致するリダイレクトから、切り詰めの効果を取り出さない。引用符付きの宛先も含む。
  - why: /dev/null への出力破棄は通常ファイルのデータを失わせず、頻繁な拒否は切り詰め規則全体の無効化を誘発する。
  - decided_by: 利用者（提案を承認）
- A2 例外はリダイレクトだけに限定し、他の宛先、変数・置換経由の宛先、シンボリックリンク経由の別名、truncate と dd の効果の扱いは変更しない。コマンド本体と宛先の置換内にある危険操作も引き続き読む。
  - why: 出力破棄への限定的な例外によって、別の破壊的効果の検出まで消してはならない。
  - decided_by: 利用者（提案を承認）

## Rejected

- R1 truncate 規則全体を無効化する、または /dev 全体を例外にする。
  - why: 通常ファイルの切り詰めや他のデバイスへの書き込みの検出まで失われる。
