# 未解決の状態を確定パスにしない修正

## Context

[事後照合](./2026-10-02-rework-ir-conformance.md)で、状態の確定条件と対象の保持に関する不一致が見つかった。
条件の成否や未知の反復回数を実行せずに推測し、危険な対象を許可していた。
既存要求を変更せず、不確定な対象を未解決として扱う修正を記録する。
製品の新しい受理条件を選択する事項は、この修正の判断と分ける。

## Agreements

- A1 ifの各分岐を独立した状態で読み、各分岐後に同じ値となる変数とcwdだけを後続へ確定伝播する。elseがなければ、その分岐を実行しない経路も含める。値が異なる変数・cwdは未解決とし、分岐内の効果は引き続き収集する。
  - why: [REQ-002](../../ir/judgment.md#REQ-002)の値が確定する場合だけ解決する契約に戻す。[照合A1](./2026-10-02-rework-ir-conformance.md#A1)の実行されない代入やcwdの伝播を防ぎ、無条件のリテラルloopと分岐共通値の解決は維持する。条件の実行器を追加せず、既存Context・Valueと標準集合による合流を使う。
  - decided_by: 実装者、既存要求への修正の範囲
- A4 未知のfor本文は、反復間状態を合流して変化しなくなるまで効果を収集する。確定値を不確定へ落とす向きだけの合流を使い、各反復で既存の判定期限を確認する。guardの構文位置は初回だけ収集し、内側解析は既存cacheを共有する。
  - why: [REQ-002](../../ir/judgment.md#REQ-002)への修正を固定二回の評価で打ち切ると、複数変数の遅延した代入連鎖で三回目以降の危険な対象を見落とす。変数2個・4個・8個の連鎖で再現し、回数を増やすだけでは根治しないため状態の合流が安定するまで確認する。
  - decided_by: 実装者、既存要求への修正の範囲
- A5 短絡演算子の後のコマンドは、実行される経路と実行されない経路の状態を合流する。条件式内でも確定値が異なる変数・cwdを未解決にする。各コマンドの効果は収集する。
  - why: [REQ-002](../../ir/judgment.md#REQ-002)の確定条件はifの本文だけでなく条件式にも適用する。`false && S=/tmp/x`の代入を無条件に実行済みとすると、分岐合流前に既存の保護対象を誤った一時パスへ置換してしまう。既存のContext合流を使い、外部コマンドの成否を実行して判定しない。
  - decided_by: 実装者、既存要求への修正の範囲
- A2 globや未知の集合のforは、反復数を一回とみなしてcwd・変数を確定伝播しない。反復前と後で共通の状態だけを保持し、変化した状態は不確定とする。本文で状態が変わる場合は不確定な反復間状態でも効果を収集し、構文位置のguard収集と内側parse cacheは共有する。
  - why: [REQ-002](../../ir/judgment.md#REQ-002)の確定条件を守り、[照合A2](./2026-10-02-rework-ir-conformance.md#A2)の未知反復後の誤ったcwdと、二回目以降の対象欠落を防ぐ。[REQ-008](../../ir/judgment.md#REQ-008)の本文の供給元分類と、確定したリテラル反復の状態継続は維持する。実際のファイル列挙や反復回数の推測は行わない。
  - decided_by: 実装者、既存要求への修正の範囲
- A3 findのexecdirで明記された固定相対対象は、起点の子集合に吸収せず未解決の対象として残す。固定絶対対象と供給元の子集合は別々に維持する。
  - why: [REQ-001](../../ir/judgment.md#REQ-001)の明記された対象を落とさず、execdirが起点自身を訪問する場合の親cwdを起点の子集合で代用しない。[REQ-002](../../ir/judgment.md#REQ-002)の確定できないパスの扱いへ戻し、[照合A3](./2026-10-02-rework-ir-conformance.md#A3)の欠落を解消する。述語や実際の探索結果を評価せず、従来の固定対象抽出とUnresolvedを使う。
  - decided_by: 実装者、既存要求への修正の範囲
- A6 HOME・TMPDIR・PWDと、それらを含む代入・語の連結・tilde・globの解決では、OSパスのバイト列を分類まで保持する。値を使用時まで保持する既存の処理は維持し、分類対象をlossyな文字列から作り直さない。
  - why: [REQ-002](../../ir/judgment.md#REQ-002)・[REQ-005](../../ir/judgment.md#REQ-005)の対象同一性を守る。非UTF-8のcwdを保護ルートに置いた実バイナリ試験で、PWDの0xffが置換文字へ変わりephemeral・allowになった。標準OsString・OsStr・Pathを使い、[入力境界の承認](./2026-10-02-ir-friction-contracts.md#A4)を表示変換の承認へ拡張しない。
  - decided_by: 実装者、既存要求への修正の範囲
