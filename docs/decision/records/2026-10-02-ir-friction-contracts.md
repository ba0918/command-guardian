# 事後照合で未定義だった製品契約

## Context

[事後照合](./2026-10-02-rework-ir-conformance.md)で、設定復旧・ログ保存失敗・shell状態・入力文字コードの条件が未定義と分かった。
実装の存在だけでは既存要求に適合すると判断できないため、利用者に選択肢をまとめて提示した。
利用者は各項目の推奨案を選択した。
以下はその製品契約であり、状態伝播の不具合修正とは別にIRへ反映する。

## Agreements

- A1 一般設定の型や値が誤っている場合は、その設定ファイル全体を不採用にして警告する。他の正常な設定層は維持する。個々のguard規則の誤りは、その規則だけを無効化する既存契約を維持する。
  - why: 壊れたファイル内のenforce=false等を残さず、復旧単位を明示する。[REQ-015](../../ir/config.md#REQ-015)の既定復帰と[REQ-034](../../ir/guards.md#REQ-034)の規則単位の例外を区別する。正常な他層まで捨てる必要はない。
  - decided_by: 利用者が推奨案を選択
- A2 影ログの専用ディレクトリとログ末尾要素のsymlink、非通常ログファイルを拒否する。保存場所がない場合や保存不能の場合は、その判定のログを省略して標準エラーへ警告し、hookの標準出力を空、終了コードを0のままにする。
  - why: 他ファイルへの追記やchmodを避け、安全に保存できないときも保存できたと誤認させない。[REQ-018](../../ir/cli.md#REQ-018)・[REQ-019](../../ir/cli.md#REQ-019)へ失敗時の例外を明記する。この条件は親の全経路やhardlinkの拒否まで保証するものではない。
  - decided_by: 利用者が推奨案を選択
- A3 複数段のパイプは、最終段が親状態を変更する場合と変更しない場合を合流し、異なる変数・cwdを未解決とする。shellの種類やlastpipe設定を推測して一方を選ばず、最終段以外の状態を親や他段へ漏らさない。
  - why: 通常bashとlastpipe等で異なる実行条件を一つの確定値として扱わない。[REQ-046](../../ir/shell-state.md#REQ-046)に前提と不確定時の扱いを明記し、[照合A6](./2026-10-02-rework-ir-conformance.md#A6)を閉じる。対象shellの文法指定だけを実行モードの保証にしない。
  - decided_by: 利用者が推奨案を選択
- A4 checkのコマンド本文と解釈するオプション名・format値はUTF-8に限定し、非UTF-8なら終了コード3で拒否する。cwdはUnixのOSパスとして受理し、非UTF-8でも引数の読取でpanicしない。入力の受理境界を明記するものであり、パス表示のlossy変換は承認しない。
  - why: [REQ-017](../../ir/cli.md#REQ-017)の終了コードだけでは本文とOSパスの文字コード境界を決められない。既存io_contract試験に対応する受理条件を記録し、[照合A7](./2026-10-02-rework-ir-conformance.md#A7)を閉じる。本文のバイト列対応は今回導入しない。
  - decided_by: 利用者が推奨案を選択
