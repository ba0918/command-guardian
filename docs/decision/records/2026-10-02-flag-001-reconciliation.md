# flag-001-reconciliation

## Context

旧 FLAG-001 は、照合を 3 回で打ち切り、修正後の 6 件を再確認していない履歴を残していた。
今回の対象は [TBL-001](../../ir/config.md#TBL-001)、[REQ-027](../../ir/guards.md#REQ-027)、[REQ-034](../../ir/guards.md#REQ-034)、[EX-031](../../ir/cli.md#EX-031)、[EX-042](../../ir/guards.md#EX-042)、[EX-044](../../ir/guards.md#EX-044) の 6 件である。
事前レビューで示された 3 件のシナリオの前提不足について、利用者が補足を承認した。
この記録は既存の決定との照合と承認された前提補足を残すもので、新しい要求や判定規則を定めない。

Position: 利用者承認済みの前提補足後、品質と仕様適合の独立レビューが完了し、6 件の静的照合を記録した。再確認の欠落は解消したため、[Flags](../../ir/FLAGS.md#Flags) から FLAG-001 の項目を除去する。実行時の動作合格や利用者の最終受け入れは宣言しない。

## Agreements

- A1 [EX-031](../../ir/cli.md#EX-031)、[EX-042](../../ir/guards.md#EX-042)、[EX-044](../../ir/guards.md#EX-044) の前提だけを、既存の決定に沿って補足する。EX-031 は、指定した一時領域ではない作業ツリーの直下の "notes.txt" 自体が未追跡であると明示し、ask と終了コード 1 を維持する。EX-042 は、同じ規則の deny 系に一致しない起動を前提に、"status" と "commit" はその規則に一致せず、"push" は "only" にないためその規則の "verdict" になることを明示する。EX-044 は、"deny"、"deny-flags"、"deny-option-values"、"deny-env"、"only" の 5 項目すべてを持たない前提にする。
  - why: EX-031 は [A8](./2026-09-30-hook-guardian-scope.md#A8)・[A9](./2026-09-30-hook-guardian-scope.md#A9)・[A27](./2026-09-30-hook-guardian-scope.md#A27) に対して、削除対象と未追跡ファイルの同一性が不足していた。EX-042 は [A48](./2026-09-30-hook-guardian-scope.md#A48) と [REQ-032](../../ir/guards.md#REQ-032) の deny 系優先を変えずに "only" の例を読めるようにする必要があった。EX-044 は [A47](./2026-09-30-hook-guardian-scope.md#A47) の 5 項目すべてがない条件と [A45](./2026-09-30-hook-guardian-scope.md#A45) の無効化を示す必要があった
  - decided_by: 利用者（事前レビューの前提補足案 3 件を承認）

## Reconciliation

### 変更前の履歴

事前レビューの報告では、元の 4 件の照合対象のうち [TBL-001](../../ir/config.md#TBL-001)、[REQ-027](../../ir/guards.md#REQ-027)、[REQ-034](../../ir/guards.md#REQ-034) は適合していた。
[EX-042](../../ir/guards.md#EX-042) はシナリオの品質確認には合格していたが、deny 系に一致しない前提の不足という仕様適合上の隙間が残っていたため、4 件すべてが合格したとは扱わない。
[EX-031](../../ir/cli.md#EX-031) の削除対象の同一性と [EX-044](../../ir/guards.md#EX-044) の 5 項目の不在も、上記の承認された前提補足の対象である。
### 変更後の静的照合

2026-10-02 に、呼出元から品質と仕様適合の独立レビューがともに完了したとの報告を受けた。対象全体とセキュリティの確認も含まれ、3 件の既存指摘は両レビューで "no_longer_visible"、新規指摘は "new=[]" だった。

| 対象 | 静的照合の結果 |
|---|---|
| [TBL-001](../../ir/config.md#TBL-001) | 元の内容が既存決定と整合している。変更なし |
| [REQ-027](../../ir/guards.md#REQ-027) | 元の内容が既存決定と整合している。変更なし |
| [REQ-034](../../ir/guards.md#REQ-034) | 元の内容が既存決定と整合している。変更なし |
| [EX-031](../../ir/cli.md#EX-031) | 利用者承認済みの対象ファイル・非一時領域の前提補足後、既存決定と整合している |
| [EX-042](../../ir/guards.md#EX-042) | 利用者承認済みの同じ規則の deny 系不一致の前提補足後、既存決定と整合している |
| [EX-044](../../ir/guards.md#EX-044) | 利用者承認済みの 5 項目すべての不在の前提補足後、既存決定と整合している |

この結果に基づき、利用者が承認した補足・再確認・記録・除去の流れに従って FLAG-001 の項目だけを除去する。実行時の動作合格、利用者の最終受け入れ、この最終記録そのものの独立レビュー完了を意味しない。

## Verification

2026-10-02 に "kotowari --version" で 0.2.0 を確認し、前提補足後の "kotowari check" は指摘なし、終了コード 0 だった。呼出元も独立に同じ検査を行い、指摘なし、終了コード 0 を確認したと報告した。
除去前の "kotowari status --format text" は error=0、notice=0、flag=1、complete false、終了コード 1 だった。
"git diff --check" は出力なし、終了コード 0 だった。
FLAG-001 除去後も "kotowari check" は指摘なし、終了コード 0、"kotowari status --format text" は error=0、notice=0、flag=0、complete true、終了コード 0、"git diff --check" は出力なし、終了コード 0 だった。
これらは形式と参照の機械検査であり、6 件の仕様適合を判断する独立レビューの代わりにはしない。
