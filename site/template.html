command-guardian reads a Bash command, works out what it would delete, truncate or format, and answers allow, ask or block. Use it from the CLI or as a pre-execution hook for AI coding agents. command-guardian は Bash コマンドを読み、何を削除・切り詰め・フォーマットするのかを取り出して、allow・ask・block を返します。CLI からも、AI コーディングエージェントの実行前フックからも使えます。

Analyzes supported Bash / POSIX sh syntax and known destructive operations. External scripts and some operations are outside its coverage; allow is not proof of safety. Scope and limits → 対応する Bash / POSIX sh 構文と既知の破壊操作を解析します。外部スクリプトや一部の操作は対象外で、allow は安全の証明ではありません。対応範囲と制約 →

Resolves known assignments and reads supported uses of bash -c, eval, find -delete and xargs without executing them.

既知の変数代入を解決し、対応する bash -c、eval、find -delete、xargs の使い方を実行せずに解析します。

Judges by what the path isパスの中身で判断する

Temporary files and clean Git checkouts are allowed. Uncommitted work asks first. System directories, .git and your home are blocked.

一時ファイルや変更のない Git 管理下は許可、未コミットの作業は確認、システム領域・.git・ホームは拒否します。

allow

The targets are temporary, explicitly allowed, or committed in Git with no changes. Exit code 0.

対象が一時領域、許可したディレクトリ、または変更のない Git 管理下にあるとき。終了コード 0。

ask

The checker cannot tell whether the loss is recoverable, such as uncommitted work. Review before running. Exit code 1.

未コミットの変更など、失っても戻せるか判断できないとき。実行前に確認してください。終了コード 1。

block

System directories, .git, your home, or a path whose value cannot be resolved. Exit code 2.

システム領域、.git、ホーム、値を解決できないパスなどが対象のとき。終了コード 2。

Example: Claude Code設定例: Claude Code

Add a PreToolUse hook for the Bash tool to ~/.claude/settings.json: ~/.claude/settings.json に Bash ツール向けの PreToolUse フックを追加します。 

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "command-guardian hook --agent claude" }
        ]
      }
    ]
  }
}

Configure it per projectプロジェクトごとに設定する

Settings layer built-in defaults, your user configuration, and the nearest .command-guardian.toml. Project configuration can only make protection stricter unless you list the project in trusted_projects. 既定値、利用者の設定、最寄りの .command-guardian.toml の順に重ねます。trusted_projects に載せない限り、プロジェクトの設定は保護を強める方向にしか働きません。 

# .command-guardian.toml
[paths]
protected_roots = ["data"]

[[commands.guard]]
program = "git"
reason = "Review the destination and commits before pushing."
verdict = "ask"
deny = [["push"]]

Optional LLM advice任意のLLM助言

From v0.2.0, a model can take a second look at commands the mechanical check allowed or asked about. It is off by default and can only be enabled in your user configuration. v0.2.0 から、機械判定が許可または確認としたコマンドを、モデルにもう一度見てもらえます。既定では無効で、有効にできるのは利用者の設定だけです。

  • Only stricter. Advice can tighten allow and ask, but never releases block or turns ask into allow.厳しくするだけ。allow と ask を厳しくできますが、block を解除したり ask を allow にしたりはしません。
  • Bounded. At most one request per verdict, with no retries and a 2-second default deadline. Timeouts and failures keep the mechanical verdict.期限つき。一判定につき要求は最大1回で、再試行せず、既定の期限は2秒です。時間切れや失敗のときは機械判定をそのまま使います。
  • Sends data. The command, working directory, mechanical result and a bounded slice of recent conversation go to TypeSafe over HTTPS. Detected secrets skip sending, but detection is incomplete.外部へ送信します。コマンド、作業ディレクトリ、機械判定、直近の会話の一部を HTTPS で TypeSafe へ送ります。秘密を検出した場合は送信しませんが、検出は完全ではありません。

Real-model accuracy and compatibility with the current TypeSafe service have not been verified. Start with observe, which only records advice. Setup, data sent and logs → 実モデルの精度と、現在の TypeSafe サービスとの適合は未検証です。まずは助言を記録するだけの observe から始めてください。設定・送信内容・ログ → 

# ~/.config/command-guardian/config.toml
[advisor]
mode = "observe"  # "off" (default), "observe" or "enforce"

Supply TYPESAFE_API_KEY through the guardian process environment, not in TOML or a command that enters shell history. Project configuration cannot enable advice. TYPESAFE_API_KEY は guardian プロセスの環境変数で渡し、TOML やシェル履歴に残るコマンドには書かないでください。プロジェクトの設定では助言を有効にできません。
